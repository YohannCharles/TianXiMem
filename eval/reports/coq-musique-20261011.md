# 链式依赖多跳检索 · MuSiQue 4 跳链上的四臂评测（2026-10-11）

**这一份回答的是**：把上一轮"题根本不是多跳"的问题修掉之后，**CoQ 在真正的链式依赖题上有没有用？**

**结论：仍然没有。** 25 道**可证的 4 跳链**上，强制多跳 **0.12 vs 基线 0.16**——
**修好 0 道、弄坏 1 道**，代价 **5.9 倍墙钟**。
⚠ **但这次的失败原因和上一轮完全不同，而且指向一个具体的、可修的地方**（见 §4）。

> 上一轮（LoCoMo `category == "1"`，25 道）的结论**不可用**：人工复核发现那批题里
> **真正的链式依赖只有 7 道**，其余是集合汇总 / 并行分解 / 一次即可。
> 全文见 [`coq-multihop-20261010.md`](./coq-multihop-20261010.md)。

---

## 1. 这次测的是什么

| 项 | 值 |
| --- | --- |
| 题 | [`../coq-musique.jsonl`](../coq-musique.jsonl)：**25 道 4 跳严格链** |
| 依赖真值 | MuSiQue 的 `question_decomposition`——hop N 的问句里写 `#k`，**字面引用第 k 跳的答案** |
| 语料 | 这 25 道题**自己的候选段落并起来**（按 `title` 去重）⇒ **一个 user / 427 段** |
| 判分 | MuSiQue 本地口径：**别名归一化后精确匹配**（**无 LLM 裁判**，不存在上一轮那个换行歧义） |
| 工具 | `tools/coq_eval.py --dataset musique-haystack`，`eval/datasets/musique.py` 的 `load_musique_haystack` |

### 为什么必须"造池子"

MuSiQue 原生**每题只有 20 个候选段落**，而这条链是
`prefetch_limit=200（两路）→ RRF 根 limit=400 → 截到 top_k=100`：

**20 < 100 < 400** ⇒ 那 20 段**原封不动全进最终 prompt**（117,760 token 绰绰有余）
⇒ 答案模型永远看到全部证据，**检索无事可做，链式依赖自动消失**。
拿这样的语料测多跳检索，测出来的只会是"多余的一轮把答案搅坏"。

并成 427 段之后，池子与 benchmark 里 LoCoMo 的 357 段**同一量级**，可比。

### 选题规则（确定性、可重放）

`select_chain_question_ids`，判据写在代码里：

1. `answerable == True`；
2. **严格链**：hop1 不含 `#` 引用，hop i≥2 **全部**含 `#k` 引用
   （⛔ 排除 MuSiQue 里"两个独立子问题在最后合并"的**并行分支**型——那类**第二轮检索不必要**）；
3. ≥3 跳，且 hop1..hop(n-1) 的答案**一个数字都不含**
   （年份/日期做不了下一跳的检索词：`#1` 会被填成 `1999`）；
4. 排序后**贪心**：新题与已选题的 hop 集合**共享 <2 个元素**才收
   （共享 ≥2 跳 = 同一条骨架换了个入口）。

⇒ 25 道**全是 4 跳**，两两最多共享 1 跳。

## 2. 结果

| 臂 | 答对 | 准确率 | 证据 ≥1 | 证据**全** | 平均延迟 | 轮数 | LLM 调用 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| **E0** 原混合链（基线） | **4/25** | **0.16** | 25 | **12** | **4.34 s** | —— | 0 |
| **E1** 强制多跳 | 3/25 | **0.12** | 25 | **14** | **25.44 s** | 60（2.4/题） | 60 |

* **修好 0 道、弄坏 1 道**（`4hop1__236903_…`）；
* **证据覆盖确实变好了**：全命中 **12 → 14**（4 道新全命中、2 道丢掉）；
* ⚠ **而那道被弄坏的题，正是 E1 新拿到"全命中"的 4 道之一**——它检索到了更多金标，**答案反而错了**；
* 精排调用 25 → **85**（每轮 60 ＋ 最终 25）；延迟 **5.9×**。

## 3. 与上一轮**对照着看**：这次的数字可信得多

| | 上一轮（LoCoMo） | **这一轮（MuSiQue）** |
| --- | --- | --- |
| 题是不是真的链式依赖 | ❌ 25 道里只有 ~0 道 | ✅ **25/25**，有 `#k` 字面依赖边 |
| 池子够不够大 | ✅ 200–350 | ✅ **427** |
| 判分口径 | ⚠ LLM 裁判，gold 渲染**超出它自己的规则** | ✅ 别名精确匹配，**无裁判模型** |
| 结论 | **不可用**（题不对） | **可用**（三个条件都满足） |

⇒ **"CoQ 在这类真多跳题上没有收益"这句话，现在有资格说了。**

## 4. ⭐ 但失败原因变了——而且指向一个**具体的、可修的东西**

上一轮我说"改写是**收窄同一问**"。**这一轮不是**：模型**真的在跳**。

从逐轮记录里直接看得见（题面与实体按 §12.5 不抄原文，改用结构描述）：

| 请求 | 原问题 | 第 1 轮的改写 | 第 2 轮的改写 |
| --- | --- | --- | --- |
| A | "…某国的发行国北面的那块地区是什么时候建立的…" | **把"the country that released Atalia"解成了 `Saudi Arabia`** | ⚠ **与第 1 轮一字不差** |
| B | "…那家为 A 国制作了某真人秀的网络的电台部门里，谁是比较重要的人物…" | **把链解成了 `ABS-CBN`**（Krystala → 菲律宾 → ABS-CBN） | ⚠ **与第 1 轮一字不差** |

⇒ **第一跳改写得完全正确**：它真的把中间实体解出来、换成了可检索的名字。
**它卡在第二跳**：拿到同样的文档之后提不出更新的查询，**原样重复** ⇒ 被程序侧的去重挡住 ⇒ 停。

三条从 60 轮里量出来的事实：

| 观察 | 数 |
| --- | --- |
| `new_query != 原问题`（**真的改了**） | **57 / 60** |
| 停止原因 | `duplicate_query` **18** · `max_rounds` 4 · `sufficient` **3** |
| `is_sufficient` | **False 57** / True 3 |
| `confidence_score` | **恒为 0.95**（60 轮一个值都没变过） |

⇒ **两件事同时坏着**：

1. **迭代不出第二跳**：模型跳一次就停在原地（18/25 请求以 `duplicate_query` 结束）；
2. **停止判据退化**：`confidence_score` **恒等于 0.95**，而 `is_sufficient` 几乎恒为 False
   ⇒ 那个"充分性"信号**没有分辨力**，`sufficiency_threshold=0.8` 更是个死门槛。
   ⚠ 上一轮我以为"0.8 是死门槛"是那批题的性质；**这一轮在真链题上复现了**——
   所以它更像**提示词/模型输出退化**，不是题目性质。

---

## 5. 这一轮**证明了**什么、**没有**证明什么

✅ **证明了**：

* 在**可证的链式依赖**（4 跳、`#k` 字面引用）、**池子够大**（427 > `top_k`）、
  **判分不含糊**（无 LLM 裁判）的条件下，强制多跳**没有收益**（0.12 vs 0.16）；
* CoQ 的**改写环节在单跳上是有效的**（把中间实体解出来换成了可检索的名字）；
* 它**迭代不出第二跳**，且**充分性信号退化**（confidence 恒 0.95）。

⛔ **没有证明**（别过度引用）：

* "链式多跳检索没有价值"——只测了 **MuSiQue 4 跳**这一种形态，
  且**只跑了一遍**（n=25，1 道题 = 4pt）；
* "CoQ 这个想法错了"——**瓶颈已经定位到两个具体环节**（迭代不出第二跳、confidence 退化），
  这两个都不是"多跳"这个想法本身。

---

## 6. 下一步（**按优先级**）

1. **先修"迭代不出第二跳"**：现在第 2 轮会原样重复第 1 轮的查询。
   可能的原因有两个，**都能单独查**：① 第 2 轮的文档里确实没有下一跳的线索
   （那是**检索**问题）；② 提示词没有逼它"必须给出与已试过的都不同的查询"
   （那是**提示词**问题）。⚠ **先分清是哪一个再动手**。
2. **再修充分性信号**：`confidence_score` 恒 0.95、`is_sufficient` 几乎恒 False
   ⇒ 这个信号目前对"停不停"没有任何信息量。**在它恢复分辨力之前，
   `sufficiency_threshold` 调多少都不会有变化**（上一轮我建议"别先调阈值"是对的，
   现在有了具体证据）。
3. **然后才谈**要不要把 2 跳的题掺进来做难度梯度。

## 7. 复现

```bash
# 造库 + 跑基线（约 5 分钟：ADD 22 批 + 25 题检索 + 判分）
uv run --env-file .env python tools/coq_eval.py \
    --dataset musique-haystack --out /tmp/coq-mus --collection coq-musique-20261011 \
    --arms e0

# 多跳臂（约 12 分钟）
uv run --env-file .env python tools/coq_eval.py \
    --dataset musique-haystack --out /tmp/coq-mus --collection coq-musique-20261011 \
    --arms e1 --skip-add
```

⚠ **`--skip-add` 必须配同一个 `--out`**：它只复用 Qdrant 集合，而 **SQLite 真源是按
`--out` 目录走的** ⇒ 换个目录再 `--skip-add`，检索会**安静地返回 `data: []`**，
看起来像"这题没有相关记忆"。工具现在有一条检查把它变成**响亮失败**。

**配置指纹**：`prefetch_limit=200` · `rrf.k=61` · `weights=[0.5,0.5]` ·
`top_k=100` · 精排开（`qwen3-reranker-4b`）· 路由 `prompt_version=v4` ·
多跳 `prompt_version=coq-original` · `max_rounds=3` · `per_round_top_k=20` ·
`sufficiency_threshold=0.8`。
