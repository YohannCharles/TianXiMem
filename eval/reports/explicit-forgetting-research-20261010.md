# 显式遗忘：论文、代码与工程方法调研（2026-10-10）

调研对象是：用户要求忘掉某项偏好或背景，后续检索和回答仍使用它。范围不含多跳。
本轮是资料调查，生产代码保持此前回退后的状态。

优先考虑的组合是**语义定位目标 + 程序执行过滤 + 追踪所有来源与派生副本**。
大模型适合判断自然语言究竟指向哪些已有记忆；实际删除、用户隔离、返回前过滤
应由程序执行。下面区分来源已经实现的机制与对 TianXiMem 的待验证建议。

## 相关工作与适用边界

| 资料 | 方法 | 对当前问题的参考价值与边界 |
| --- | --- | --- |
| [Mem0 论文](https://arxiv.org/html/2504.19413v1)（2025） | 抽取候选事实，检索相似记忆，由 LLM 选择 ADD / UPDATE / DELETE / NOOP，程序应用操作 | 参考语义目标定位和结构化操作。论文中的 DELETE 主要描述矛盾信息处理；不能据此宣称已解决任意显式遗忘 |
| [LangMem 官方工具](https://langchain-ai.github.io/langmem/reference/tools/) / [执行代码](https://github.com/langchain-ai/langmem/blob/main/src/langmem/knowledge/tools.py) | 模型调用管理工具；删除要求已有 memory ID，程序在相应 namespace 内执行 store.delete | 可参考“模型选 ID，程序删 ID”。提供删除工具不代表模型一定调用正确，也不保证清理原始对话等其它存储 |
| [GateMem 论文](https://arxiv.org/html/2606.18829v1) / [代码](https://github.com/rzhub/GateMem)（2026 预印本） | RAG-Policy 使用策略元数据、检索过滤与提示；分别测正常任务、访问控制、删除后恢复 | 检索需要判断记忆是否仍可使用。论文发现策略过滤存在正常任务效用损失，不能只看泄漏降低 |
| [Zep v3 删除文档](https://help.getzep.com/deleting-data-from-the-graph) | 按 episode 与派生节点、边的关联执行删除，保留仍有其他 episode 支持的对象 | 删除一次对话与忘掉某个事实的范围不同；文档明确共享节点的名字和摘要不会随 episode 删除而重新生成，可能残留内容 |
| [Deployment-Time Memorization](https://arxiv.org/html/2606.10062v2)（2026，本文使用 v2） | 对比只清原文、清原文并重做摘要、全层清除、全层脱敏等删除策略 | 支持同时处理原文、派生摘要及索引表示。遗忘实验仍是小规模高熵标记测试，不能直接外推语义偏好遗忘 |
| [Memora 论文](https://arxiv.org/html/2604.20006v1) / [代码](https://github.com/geniesinc/Memora)（2026 预印本） | 分开检查有效记忆是否出现在答案中，以及失效或删除的信息是否缺席 | 适合借鉴评测设计：同时防止旧信息复用和过度过滤，并非一个保证遗忘成功的算法 |
| [Oblivion 论文](https://arxiv.org/html/2604.00131v1) / [代码](https://github.com/nec-research/oblivion)（2026 预印本） | 随时间降低记忆可访问性，按使用情况强化，需要时再激活 | 适合容量和干扰管理；允许重新激活，因此不能单独承担用户明确要求立即遗忘的语义 |

## 代码核对中需要保留的区别

### 论文方案、提示模板、当前执行路径不是同一件事

Mem0 论文描述四类更新操作；其 [prompts.py](https://github.com/mem0ai/mem0/blob/main/mem0/configs/prompts.py)
也有更新和删除提示。但本次查看的 main 分支
[_add_to_vector_store](https://github.com/mem0ai/mem0/blob/main/mem0/memory/main.py)
已经采用 `ADDITIVE_EXTRACTION_PROMPT` 的分阶段抽取路径。因此，不能只见到旧提示
就认定当前默认 add 会自动执行论文中的全部操作。

同一文件的显式 `delete(memory_id)` 能删除向量存储中的记录；`_delete_memory`
还会写入含旧值的历史。**活动检索索引删除不等于所有持久化副本均已擦除**。
这里登记的是 2026-10-10 的源码阅读观察，main 链接会随上游更新，不是固定版本的行为承诺。

Zep 云服务文档与 [Graphiti 开源代码](https://github.com/getzep/graphiti/blob/main/graphiti_core/graphiti.py)
也应分别核对：本次看到的 `remove_episode` 按创建 episode 判定部分边的删除，
不能把云端 v3 文档的共享来源规则直接套给这个开源函数。

### 脱敏标记与阻止重放的控制事件不是同一个机制

Deployment-Time Memorization 的 `tombstone` 是在所有层将目标标记替换为
`[REDACTED]` 并重新计算 embedding。它不是“永远禁止旧记录重放”的注册表。
给 TianXiMem 增加持续生效的遗忘事件、防止旧 Add 或索引重建使信息恢复，
属于下面提出的工程设计，不能算作该论文已经验证的结论。

## 与本地失败的对应关系

本地事实依据见 [PersonaMem 遗忘题池分析](personamem-20261009.md)。
已观察到的问题包括：`forget that I…` 没被识别，以及用户遗忘命令被删掉、
旧助手回复中的同义偏好仍保留。说明仅扩大几条字面正则无法覆盖整个问题。

需要分别处理三个对象：

1. **控制事件**：用户正在要求遗忘；必须可追踪，不能因为正文包含目标词就先删掉它。
2. **被遗忘的事实**：例如用户喜欢手工制品；要定位同义表达和多次重复。
3. **携带它的来源**：用户原话、助手个性化建议、事实索引、摘要、扩窗片段。

来源关联不一定要用图数据库。已有记录 ID 加来源侧、句子范围和派生关系，也可以
用于定位需要过滤的片段。整条 QA 常包含其它有效信息，直接删整条容易误伤。

## 对 TianXiMem 的候选路线（建议，尚未实现或验证）

当前 [项目约束](../../CLAUDE.md) 是 Add 不用 LLM 抽摘要，Search 返回证据，
最终回答由 AML 生成。Mem0 的模型写入流程不能作为当前实现的直接替换。
首先可以在离线片段实验中验证语义识别，确认收益后再决定在现有约束内如何接入。

候选内部数据关系：

```text
control_event:
  user_id, operation, target_fact_ids, scope,
  source_record_id, source_span, event_sequence

fact_source:
  fact_id, record_id, question_or_answer, span, derivation
```

这里的 ID、范围和操作来自有来源的控制句及已有记忆，不能让模型生成最终答案，
也不能允许模型选择其它用户的 ID。具体同义范围需要独立人工验证。

候选流程：

1. 定位用户控制句，将它与普通偏好陈述分开。
2. 在该用户的候选事实及来源中定位目标；模型只返回受限的操作、ID 和来源范围。
3. 保存控制事件，构建当前可检索视图；已知禁用对象不参与返回候选选择。
4. 对原文、助手重复、事实、摘要等来源实施对应过滤；扩窗和打包结束后再检查一次，
   防止被禁用的信息通过邻居片段重新进入返回结果。
5. 索引重建与旧记录重放检查控制状态；新授权必须有可追踪的新用户指令。

这是逻辑抑制设计，保留原文用于重建时不能宣称已经物理擦除。若目标升级为真正的
持久化删除，还需处理真源、索引、摘要、缓存及历史等实际存在的副本。

控制提示可以作为辅助，但不能代替目标过滤。自行生成回答后的检查与重新生成，
可用于本地诊断；当前 AML 接口没有把最终回答环节交给 TianXiMem。

## 按用户要求先做手动片段验证

先固定真实失败片段与同义改写，不修改生产代码：

| 片段类型 | 验证目标 |
| --- | --- |
| 手工制品偏好，`forget that I…` | 识别自然句式，定位旧手作偏好及助手相关建议 |
| 图像小说偏好，多种同义表达 | 保留控制含义，过滤旧个性化证据，不能只移除命令句 |
| 乳糖不耐受或反酸背景 | 后续答案不再用旧健康背景解释推荐，同时保留当前问题的明确要求 |
| 偏好已进入摘要或扩窗邻居 | 原文过滤后，派生或相邻片段不能把目标带回 |
| 旧历史重放、新授权、不同用户 | 控制状态有正确范围和顺序，不能误伤其它用户或自动恢复旧事实 |
| 未要求遗忘的普通题 | 检查有效信息是否仍可使用，防止只靠扩大删除范围降低泄漏 |

例如，用户忘掉乳糖不耐受后，现在问“不放牛奶的浓汤”，仍可推荐椰奶和土豆。
当前问题已经提供不放牛奶的约束；不需要重新调用旧健康背景，也不应因此拒绝推荐。

片段通过后才修改代码并做小规模 HTTP 配对，再跑 PersonaMem 全部遗忘子池。
正式对照前还需冻结选项顺序、prompt 与模型设置，记录最终选项解析和结束原因；
完整分母保留技术与格式失败。比较正常回答、禁用信息残留和误过滤，不能将
论文实验、本地表现或合成探针的改善直接当作 AML 分数改善。

本轮只新增此调研报告；没有安装外部项目，也没有恢复遗忘实验开关或启动评测。
