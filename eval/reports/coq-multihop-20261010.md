# 多跳执行器（Chain-of-Query）· 真实数据四臂评测（2026-10-10）

**这一份回答一个问题：`MULTI_HOP` 那条路值不值得开？**
**结论：不值得。** 在 25 道 LoCoMo 多跳题上，强制走多跳 **0.56 vs 基线 0.72**——
**修好了 0 道、弄坏了 4 道**，代价是 **7.3 倍墙钟**。⇒ `agentic.enabled` **保持 `false`**。

> ⚠ 结论是**负面的**，而报告照实写。方案 §12 明说"全部实验结果必须来自真实执行，
> 不能编造"，也没说结果必须是好的。

## 2. 四臂结果

| 臂 | 开关 | 答对 | 准确率 | 证据 ≥1 / 全 | 平均 Search 延迟 | 平均轮数 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| **E0** 原混合链（基线） | 全关 | **18/25** | **0.72** | 23 / 10 | **2.48 s** | —— |
| **E1** 强制多跳（绕过路由器） | `agentic.force` | 14/25 | **0.56** | 23 / 10 | **18.23 s** | 1.72 |
| **E2** 路由器 ＋ 多跳 | 两个都开 | 17/25 | **0.68** | 23 / 10 | 4.68 s | —— |
| **A** 消融：每轮**不**精排 | = E1 但 `round_rerank_enabled=false` | 13/25 | **0.52** | 20 / 7 | 13.86 s | 1.92 |

### ⭐ 结论一：多跳**修好 0 道、弄坏 4 道**

逐题对比 E1 与 E0：

| | 题 |
| --- | --- |
| E0 对 → **E1 错** | `conv-26#q0050` · `conv-30#q0018` · `conv-41#q0006` · `conv-41#q0017` |
| E0 错 → **E1 对** | **（一道都没有）** |

⇒ 这不是"涨跌互现"（那还可以说样本小），而是**单向的**：多跑的那几轮**没有带回任何
基线没找到的答案**，只是把 4 道本来对的题搅坏了。

### ⭐ 结论二：机制是"轮数增加了，证据没有增加"

**证据覆盖四臂完全一样**（E0 / E1 / E2 都是 `23/25` 至少命中一条、`10/25` 全部命中）。
也就是说：**CoQ 确实改写出了新的查询，那些查询也确实召回了新候选
（三轮去重后 601 条），但金标证据一条都没多。**

这与结构完全吻合——E1 相比 E0 唯一多出来的东西是**更多候选**，而
§4 早就判过"**检索不是瓶颈，选择与排序才是**"。多拿 600 条候选进来，
精排要在更大的池子里挑同样多的名额，**噪声项变多、正确项的名次未必变好**。

### ⭐ 结论三：**路由器在这 25 道"多跳题"上一次都没选 `MULTI_HOP`**

E2 的路由分布：**`DEFAULT` 15 + `COUNT` 10 + `MULTI_HOP` 0**。
⇒ E2 的 0.68 ≈ E0 的 0.72 **再减掉路由器本身的开销**（逐题只差 1 道：`conv-41#q0006`）。

⚠ 这**不是**路由器的 bug，而是**两套"多跳"定义不一样**：

* 数据集说的 `category == "1"` 是**答案类型**（要跨多条记忆才能答出来）；
* 路由器判的 `MULTI_HOP` 是**检索依赖结构**（缺一个必须先去检索的中间实体）。

[`../../CLAUDE.md`](../../CLAUDE.md) 那份路由样本早写过这条：

> LoCoMo 标成 `category=1` 的题、**按本判据有一半其实是 `DEFAULT`**。

这次实测把它推到了**全部 25 道**。⇒ **"给多跳题接一个多跳执行器"这个前提本身要重审**：
我们的路由器认为它们**不是**多跳题。两个判断最多只有一个对，而**目前没有第三种证据**。

### 结论四：§12.4 的消融（每轮精排值不值）——**这一批量不出来**

A（不精排）0.52 vs B（= E1，精排）0.56：差 1 道题，落点互有胜负
（E1 独对 3 道、A 独对 2 道）⇒ **净 +1，n=25，完全是噪声**。

⚠ 但**证据覆盖那条线是单向的**：`20/7` → `23/10`，**两个数都升**
⇒ 每轮精排**确实**把更多金标证据送进了文档列表。
⇒ **可以说的是**："每轮精排改善了进文档的证据质量"；
⛔ **不能说**的是："每轮精排提高了准确率"——那一条这一批不支持。

### 结论五：成本

| | 基线 E0 | E1（多跳） | E2（路由+多跳） |
| --- | ---: | ---: | ---: |
| 平均 Search 延迟 | 2.48 s | **18.23 s（7.3×）** | 4.68 s（1.9×） |
| 最大 | 4.24 s | **34.86 s** | 9.75 s |
| 精排调用 / 25 题 | 23 | 43（每轮）＋ 25（最终）= **68** | 24 |
| LLM 调用 / 25 题 | 0 | **43** | 25（全是路由） |
| 路由本身 | —— | —— | 2.25 s / 次 |

⚠ E2 的 4.68 s 里有 2.25 s 是**路由器**：**一次分类比整条混合检索链还贵**。
⚠ E1 的 LLM 调用是 **43 次 / 25 题**（平均 1.72 轮），停止原因：
`duplicate_query` **14**、`sufficient` **11**。
⇒ **一半以上的请求，模型第二轮提不出新查询**（原样回吐原问题）而停下——
§7.5 说那是一种**正常**停止，但它同时也说明**这种题它没什么可改写的**。

### 机制：逐轮数据说了什么（E1，43 轮 / 25 题）

⚠ 这一节读的是 `e1-rounds.json`（逐轮落盘，§11 要求的"实验模式可重建每轮"）。

| 观察 | 数 |
| --- | --- |
| 每题的轮数 | 1 轮 ×11 · 2 轮 ×10 · 3 轮 ×4 |
| `is_sufficient = true` 的轮次 | **10 / 43** |
| 停止原因 | `duplicate_query` **15** · `sufficient` 10 |
| `new_query` **就是原问题**的次数 | 12 / 43 |
| `confidence_score` 范围 | **0.85 – 0.95**（最小值 0.85） |
| JSON 提取方式 | `direct` **43/43** |
| 多轮请求里，后续轮**新增的候选** | 平均 **+7.5 条**（占并集 13%–44%） |
| 多轮请求里，后续轮**新增的选中证据** | **9 / 14 次是 0 条** |

三条从这张表里读出来的事：

1. **改写是"换个说法问同一件事"，不是"跳到下一个实体"。**
   典型（`conv-26#q0058`，⛔ **原文按 §12.5 不抄进来**）：
   一句问"某人决定了哪条职业路线"的问题，三轮被改写成
   "**具体**是哪条职业路线" → "具体是哪**一类**咨询 / 心理健康岗位"
   —— 三轮都在**收窄同一个问题**，没有一轮去问"那个职业的前置条件是什么"。
   所以后续轮确实召回了新候选（平均 +7.5 条），但它们是**同一件事的邻近块**，
   不是那条**缺失的中间证据**。⇒ 这正是"证据覆盖四臂相同"的原因。

2. **`sufficiency_threshold = 0.8` 在这批数据上是个死门槛。**
   43 轮的置信度**最低 0.85**，一次都没低于 0.8 ⇒ 提前停止完全由 `is_sufficient` 决定。
   ⚠ 这说明那个阈值（§7.4 给的 0.8）**没有被这批数据检验到**——
   `low_confidence` 这个停止原因一次都没出现。**别因为它"配了"就以为它在起作用。**

3. **解析层那套两阶段提取在这批上没被用到**（43/43 都是干净 JSON）。
   ⚠ 这**不是**"可以删掉回退路径"的理由：提示词的输出形状是模型的自由，
   这一批守规矩不代表下一批守；而回退路径存在的意义正是那种时候。

## 3. 跑之前先修的两个**过程缺陷**（都必须留痕）

这两个都不是多跳算法的问题，而是**实验本身差点给出错结论**：

### ① 四臂都**没有精排**（第一轮跑）

`.env` 里 `TIANXIMEM_PROFILE=local` ⇒ [`../../configs/local.yaml`](../../configs/local.yaml)
**刻意把精排关掉**（开发期省时间）。于是：

* 基线是"**没有精排**的基线"——不是提交口径；
* §12.4 要测的那对对照（A 与 B）**两个臂配置完全相同** ⇒ 差异恒为 0。

⚠ **它不会报错**：分数照出（0.68 / 0.60 / 0.64 / 0.60），表格照打，
只有 `report.json` 里那个 `rerank.calls = 0` 是线索。
⇒ 工具现在**显式钉住 `rerank.enabled = true`**（`--no-rerank` 才能关），
不看 profile。上面 §2 的全部数字是修正后重跑的。

### ② 证据覆盖率**恒为 0**（同一轮）

第一版覆盖率拿 `Question.evidence`（形如 `D2:8` 的**消息 id**）去返回文本里找——
而那个 id **我们永远不输出**（我们的 `content` 是 QA 块的渲染文本）。
⇒ 四臂一律 `0/25`，看起来像"一条证据都没检索到"，**而那是假的**。
⇒ 改成用金标消息的**原文**做包含判定（见 §5 的口径说明）。

## 5. 追加复盘：**为什么"多跳推理"反而更差**（2026-10-10，未重跑）

⚠ 这一节全部来自**已落盘的产物**（`e{0,1}-hits.json` · `e1-rounds.json` · `*/input.jsonl` ·
`*/labels.jsonl`），**没有重跑任何请求**。

先把 4 道翻转题的现场摆出来（E0 对而 E1 错）：

| 题 | 类型 | E0 答案 | E1 答案 | 裁判理由 |
| --- | --- | --- | --- | --- |
| `conv-30#q0018` | 列清单 | 命中 | 命中 **＋ 多一项** | `adds an extra distinct fact` |
| `conv-41#q0017` | 列清单 | 命中 | 命中 **＋ 多三地** | `extra locations not present in the gold` |
| `conv-41#q0006` | 列清单 | 命中 | **少一项**（掉了 gym） | `omits the gym` |
| `conv-26#q0050` | 列清单 | 命中 | **少一项**（掉了"身体变化"） | `completely omits …` |

⇒ 四道题**全是"列出所有 X"型**，失败形态只有两种：**多答**（2 道）与**漏答**（2 道）。
而裁判口径对两者都不宽容——判据原话是
**"extra non-contradictory items generally count as wrong for lists of distinct facts"**。
⇒ **这条链对"多带一点相关记忆"是负收益的。**

### 机制一（占主导，且**不是**多跳的错）：最终候选池被腰斩 4 倍

| | E0（基线） | E1（多跳） |
| --- | ---: | ---: |
| 每题最终候选池 | **100**（`HybridRetriever` 直接按请求的 `top_k` 截） | **23**（中位，min 20 / max 36） |
| 答案阶段实际读到的证据 | 625 917 字符 | **181 997 字符（−71%）** |
| 证据更少的题数 | —— | **23 / 25** |

**原因在代码里，不在模型里**：每轮的精排结果**只有 Top-20** 进入 `state.ordered_ids`
（方案 §8.1 / §9.2 就是这么规定的）——**第一轮召回的那 100 条里，另外 80 条被丢掉了**。
于是"多跳"那条路**从比基线小 4 倍的池子里**选最终证据。

⚠ 这与 PRD §9 的"**合并而非替换**"是相抵的：那条要求 agent 的产出与**初始候选**合并，
而我们的第一轮虽然跑的就是原问题、却只把它的 Top-20 交了出去。
⇒ **这是本阶段最该先改的一处，而且它与 CoQ 本身好不好无关。**

### 机制二：`MULTI_HOP` **绕过了共同取证**（所以 E0↔E1 不是干净对照）

E0 的 §14 记录：`grounded_evidence.outcomes = {no_plan: 22, selected: 2, unsupported_walk: 1}`，
`projections = {fact: 2}`，`rerank.calls = 23/25`。
⇒ **25 题里有 2 题走的是那条确定性取证短路**（`filter` 算子），返回 3–4 段精确事实；
而这两题正是 `conv-30#q0018` 与 `conv-41#q0006`——**两题在 E1 里全丢了**。

⚠ `_search` 里三条路是**互斥**的：`route is MULTI_HOP` ⇒ 取证分支**不会被尝试**。
所以 `agentic.force` 不只"换了后半程"，它**把起点也换了**。
⇒ **"强制多跳"这一臂测的不是"多跑几轮"，而是"多跑几轮 且 不做确定性取证"。**
（E2 只掉 1 道，正是因为它还有 `COUNT` 分支保住了那条路。）

### 机制三：联合精排 Query 会把话题带偏

`conv-41#q0017`（问"美国哪些地区"）的第二轮改写是
"**John 的 Pacific Northwest 之行与 East Coast 之行分别去了哪些州/城市**"，
而**最终精排 Query = 原问题 ＋ 实际执行过的改写**（§9.1 的联合精排）。
⇒ 与那句改写同话题的**其他旅行记忆**被排了上来，答案里就多了 **Oregon / England / Spain**。
⚠ 这一条是**我们自己的设计选择**（§9.1），不是提示词或模型的毛病；
`agentic.final_rerank_query_mode` 那个 `original` 档就是为它留的对照，**本阶段没跑**。

### 机制四：改写本身是"收窄"，不是"跳下一跳"

前面 §2 的逐轮数据已经写了：43 轮里 12 轮的 `new_query` 就是原问题，
多轮请求里后续轮平均只带回 **+7.5 条新候选**，而**没有一条新的金标证据**。
⇒ CoQ 在这里买到的是"**更多轮**"，付出的却是"**更少的最终证据**"——
因为机制一把候选池压到了 20/轮。

### 于是"为什么听起来更好却更差"

1. **它换掉的不只是轮数**：起点从"取证或 100 条混合候选"变成"23 条多跳候选"；
2. **它的收益是"更多候选"，而收益项被机制一抵消了**——池子反而小了 4 倍；
3. **它的成本是"话题漂移"**——改写引入的新话题进了最终排序；
4. **裁判对"多带一点"零容忍**，把每一次漂移都变成一次判错。

⚠ **这四条里，只有第三、四条与"多跳思维"本身有关；第一、二条是接线问题。**
⇒ **不要在改这三层之前就下"CoQ 没用"的结论**——本报告 §2 的那张表测的是
"当前接线的 CoQ"，不是"CoQ 这个想法"。

## 6. 待办与已知边界

1. **§12.4 的消融要重跑**：只有一次 25 题的观测，净 +1 道不能下任何结论。
   要回答"每轮精排值不值"，至少要多次重复（或把题量提到 100+）。
2. **"多跳"的定义要对齐**：数据集类目 vs 路由器判据，两者在 25/25 上不一致。
   在弄清"哪一边更接近 AML 的真实问题分布"之前，**不要按数据集类目标签去调路由器**。
3. **本轮只跑了两个关键的臂两次、E0/E2 各一次**，没有换裁判、没有换种子。
   ⚠ 25 题的分辨率是 **4pt / 道**，读表时按这个尺度看。
4. **没有做「单轮扩大 Top-K」那一路对照**（§12.6 列了但本阶段不做）。
   它才是"多拿候选到底有没有用"的干净对照——多跳这一路把"候选变多"与
   "查询被改写"两件事绑在一起了，**分不开**。
5. `coq-eval-20261010` 这个隔离 collection **跑完保留着**，删它：
   ```bash
   curl -X DELETE "$TIANXIMEM_QDRANT_URL/collections/coq-eval-20261010"
   ```

## 7. 口径（读数字之前先读这里）

* **证据覆盖是"文本包含"口径，不是 id 映射**：金标那条消息的原文出现在返回的
  `content` 里就算命中。⚠ 它会**高估**（同一句话出现在别的记忆块里也算）。
  ⇒ 当**上界**读。要精确的召回率，得先有"LoCoMo 消息 id → 我们的 `memory_id`"那层映射，
  而两者的切分口径本来就不同（我们是 QA 块、它是消息）。本仓**还没有**这层映射。
* **`E1` 就是 §12.4 的 B 臂**：两臂配置逐字相同，所以没有重复跑。
* **`--limit 3` 的三段对话**：与台账里那条基线同源，但题目不同，分数不可互比。
* **判分**走既有的 `pipeline_locomo-refined.py`（answer → evaluate），与全仓其它评测同一个口径。
* 逐题产物（含数据集原文的 Query）在 `runs/coq-20261010/`，**不进 Git**（`.gitignore`）。

`sufficiency_threshold = 0.8`。
