# eval/smoke/ — 只打真 AML 的那一层

**PRD**：§2.4（机会成本）、§13（A1 的契约校验）、§17.1（S1/S2/S3）

## 要写什么

```text
preflight.py    契约预检（**跑 Smoke 之前先本地过一遍**）
quota.py        Smoke 配额与节流记账
s1_discriminator.py   **S1 的最小判别实验**
s2_probe.py     S2 探针（切批口径）
s3_probe.py     S3 探针（created_at 是否被消费）
```

## 为什么单独一层

**Smoke 的额度是稀缺资源**：每轨道 **≤30 次**、**每小时 1 次**、**不进榜**（§2.4）。

它**只能**用来做两件事，**不能当调试器**：

1. **验证契约合规**（§13 要求 A1 必须能通过 Smoke 契约校验）
2. **消除本地无从验证的未知**（§17.1 的 S1–S3）

**任何能在代理评测上回答的问题，都不该花 Smoke 的额度。**

---

## 1. 契约预检（`preflight.py`）

**在花掉任何一次 Smoke 之前，把 [`../../docs/contract.md`](../../docs/contract.md) §4 的清单在本地自动跑一遍。**

最值得自动化的三条——它们最容易在加了邻域扩展之后悄悄破掉，而**破掉时不报错**：

| # | 断言 |
| --- | --- |
| **精确计数** | `len(data) <= top_k`，**含邻域扩展加进来的槽位**（它们占名额） |
| **`created_at` 始终存在** | 日粒度或 `""`，**不能缺字段** |
| **`score` 单调递减** | 且**不是**原始 RRF 分数 |

`Makefile` 里预留了 `make contract-check` 目标（尚未实现）指向这里。

## 2. S1 判别实验（`s1_discriminator.py`）—— 本目录的头号任务

> **S1 是悬而未决清单里唯一"信息不足且后果最重"的一条**（§17.1）。
> **Smoke 第一次跑通后，第一件事就是设计一个能判别它的最小实验。**

**要回答的**：AML 从返回项里取哪个字段（`content`？`text`？），取出来的是**字符串还是整个 dict**。

**两个不报错的失败模式**：

| 模式 | 后果 |
| --- | --- |
| AML 按 **dict** 处理我们的返回项 | 模型读到 `{"id": ..., "content": ...}` 形式的**原始 JSON**，正文被淹在结构里 |
| CL-Bench 路径读 **`text`** 字段（缺 `text` 的项**被直接跳过**） | 我们的记忆被**整批丢弃**，退化成字面量 `(no memories)` |

**判别手段**（§17.1）：**Smoke 不返回答案文本**，只能用端到端信号——

> **加一条只有它能回答的记忆，看分数是否变化。**

**兜底方案（不要提前上）**：返回项里同时带 `content` 与 `text`。AML 规范要求 `content`，**多余的键通常被忽略**——**但这属于契约外的赌注，要等 Smoke 的实测结果再决定。**

**⚠ 这件事越早越好**（§17.1 的"何时清掉"列写的是"Step 6 之前，**越早越好**"）——因为若 S1 的答案是坏的那个，**§11.3 的整个打包策略都要重做**。

## 3. S2 / S3 探针

| # | 探针测什么 | 注意 |
| --- | --- | --- |
| **S2** | 线上是否真按 20 条 / 2,000 词切批，"Adapter 计的词"怎么算 | **本地复现不了词数那一路**（"Adapter" 官方从未定义，§12.3 第 5 条）。不消除的后果是 `pending` 埋点与线上对不上，**误判配对质量** |
| **S3** | `created_at` 是否被 CL-Bench 那条路径消费 | 不消除就白白放弃该数据集的时间信息 |

**两者都是 Step 6 前清掉即可**——但 S2 有一条**只在真实切批下才成立**的推论：**本地看到的 `pending_*` 数字不能用来判断配对质量**，只能用来验证续接逻辑自洽。

## 4. 配额记账（`quota.py`）

**必须记账，因为额度是硬的**（§2.4）：

| 层 | 限制 |
| --- | --- |
| **Smoke** | 每轨道 **≤30 次**，**每小时 1 次** |
| **Full** | 每 Key 每轨道 **2 次**，第二次需等第一次完成 **30 天后**；**一旦接受即版本冻结** |

**台账本身写在 [`../../docs/submission.md`](../../docs/submission.md)**——那是**人看的记录**（哪次 Smoke 测了什么、结论是什么、Full 冻结的是哪个版本）。本目录的 `quota.py` 只做**机械节流**（阻止第 31 次、阻止 1 小时内第 2 次）。

> **为什么"版本冻结"要单独记**：**不能因成绩不佳撤换**（§2.4）。所以"这次 Full 提交的是哪个 commit + 哪份配置"是**必须留痕**的信息——**它决定了赛后能否复现**。

## 一条纪律

**任何能在代理评测上回答的问题，都不该花 Smoke 的额度。**（§2.4）

**推论**：本目录的每一行代码都应该指向 §17.1 的某一条 S，或指向 §13 的 A1 契约校验。**做不到这一点的脚本，请放到 `eval/harness/` 或 `eval/experiments/`。**
