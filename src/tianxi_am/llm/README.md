# llm/ — LLM 后端

**PRD**：§2.3（模型规定）、§12.1 R1（模型替换）

## 要写什么

```text
base.py            LLM 协议（一次调用 / 工具调用）
gpt_4o_mini.py     提交与本地评测用（§2.3 唯一允许的 LLM）
qwen_local.py      开发期替代（**不进提交链路**）
```

---

## 为什么单独一个目录

**因为它是 R1 的接缝。** §12.1 的偏离是"开发期用 qwen3.5-9b，提交前换回 `gpt-4o-mini`"——**LLM 是整个系统里唯一会被整体替换的组件**。

若调用点散落在 `agent/` 各处，Step 5 就不是"换一个实现"，而是"改一批调用方"，**而 Step 5 明确不可与任何设计改动合并**（R1 对冲 4）——那一步只允许做一件事。

---

## 使用范围（窄，这是有意的）

| 路径 | 是否调用 LLM |
| --- | --- |
| **`Add` 路径** | **完全不调用**（§7.2）——embedding 是唯一的 Add 侧成本 |
| **`Search` 路径** | **只在 `agent/` 里调用**，且仅当 Evidence Checker 判定不足（§8 / §9） |

> **这是 v1 的一个刻意属性**（§7.2）：Add 侧的成本**只与内容有关**，缓存后即成为**一次性成本，与迭代次数无关**。若在 Add 路径里加了任何 LLM 调用（摘要、Fact 抽取、实体归并…），这个属性立刻失效——**而 v1 已经明确不做这些**（Query Analyzer 已砍、实体层收在附录 A）。

**因此**：任何"顺手在写入时抽个摘要"的想法，都属于 v2，**且会同时破坏成本属性与 §11.3 的"原文优先"**（§11.3 明确 v1 不产生任何合成文本）。

---

## 模型规定（§2.3，不可协商）

| 组件 | 规定 |
| --- | --- |
| Embedding | **只能用 `text-embedding-v4`** |
| **LLM 相关组件** | **只能用 `gpt-4o-mini`** |
| Reranker | **不作规定** |

**开发期替换是团队主动接受的偏离**（§12.1 R1）——代价是**本地标定出的所有阈值、权重、排序策略在切换后都不保证成立**。

**四条对冲**见 [`../../docs/decisions.md`](../../../docs/decisions.md) D2。与 LLM 直接相关的两条：

- **所有阈值必须是配置项**（对冲 3）——包括 agent 的轮数、工具参数、prompt 相关常量
- **切换要单独占一个阶段**（对冲 4）

---

## 禁止事项（法律）

**数据不得用于训练**（§12.5 / §17.3 P2）。**"微调模型"不是暂不实现，是不允许**——AML 数据条款 + CLBench 许可证**双重封死**，**无对冲余地**。

> ⚠ **这条尤其针对本目录**：`gpt-4o-mini` 不能微调（也不允许），但**本地 qwen3.5-9b 可以**——所以有人会在 Dev 阶段觉得"反正本地模型，微调一下没关系"。**不允许。**
>
> 另外 §11.2 的 reranker 是**自托管开放权重**的，那是**另一个容易伸手去微调的地方**——同样不允许。
>
> **证据范围提醒**：归档里**没有**这两条条款的出处（全库检索 `only for the evaluation` 等措辞零命中），属**单边来源**，引用前须回原始页面/许可证文件复核。**但结论不变。**
